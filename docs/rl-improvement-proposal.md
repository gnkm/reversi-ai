# 強化学習 (自己対局) 改善提案書

この提案書は、カタログ個体「強化学習 (自己対局)」（`SPECIMEN_ID = "rl"`）について、局数を増やしても順位が動かなかったことを受け、今後の設計方針と検証手順をまとめるものである。1 章で背景を、2 章で方針を、3 章で検証手順を、4 章でカタログ上の扱いを書く。

数値の正本は総当たり JSON と `models/rl.json` である。本文の小数は閲覧用に丸めた写しであり、再計算して正本にしない。2 章・3 章に出てくる局数・段階数・マス数などの数値は、特記しない限り設計上の目安であり、測定結果ではない。提案書の作業稿であり、[`docs/source-of-truth/`](source-of-truth/) には置かない。shall は書かない。

## 1. 背景

### 1.1 いまの学習

算法は線形 TD(0) である。実装は [`strategy/src/reversi/train/rl.py`](../strategy/src/reversi/train/rl.py)、対局時の読み出しは [`strategy/src/reversi/agents/rl.py`](../strategy/src/reversi/agents/rl.py)、解説は [`docs/catalog/rl.md`](catalog/rl.md) である。WTHOR は使わない。

盤の特徴 \(\boldsymbol{\phi}(B)\) は黒・白・空の 3 平面、あわせて 192 次元の 0/1 である。価値は \(v(B) = b + \mathbf{w}\cdot\boldsymbol{\phi}(B)\) である。各マスは黒・白・空のどれか一つなので、実質はマスごとの位置点数表に切片を足したものである。手数・パリティ・フロンティアなどは入らない。

自己対局は ε-greedy、学習率も ε も減衰しない。毎回ゼロから学ぶ。対局時は着手直後の \(v\) がいちばん高い合法手を選ぶ（白番は符号反転）。同点は a1…h8 である。

既定の学習量は次のとおりである。

| 引数 | 既定 |
| --- | --- |
| `--games` | 400 |
| `--alpha` | 0.001 |
| `--epsilon` | 0.1 |
| `--seed` | 0 |

### 1.2 局数を増やしても順位は動かなかった

既定 400 局の総当たりは [2026-09-21 19:09](benchmarks/archive/2026-09-21-1909.json) である。その後 `--games 5000` で学習し直した記録が [2026-09-21 19:52](benchmarks/round-robin.json) である。推移は [`history.md`](benchmarks/history.md) である。

| 記録 | 局数 | 順 | 勝-分-負 | 点 | 石差 |
| --- | ---: | ---: | --- | ---: | ---: |
| 19:09 | 400 | 5 | 9-1-10 | 9.5 | −162 |
| 19:52 | 5000 | 5 | 9-1-10 | 9.5 | −122 |

勝ち点と順位は同じである。ミニマックス・αβ・定石・生成 AI (Jev) にはどちらも 0 勝 2 敗である。位置評価との差も小さく、5000 局時点では強化学習 9.5 点・位置評価 9 点である。

400 局から 5000 局は 12.5 倍である。この倍率で順位も勝ち点も変わらない以上、いまの表現のまま 10 倍の 5 万局にしても、定石や読みに勝つ種類の伸びは期待しにくい。学習率 0.001 と ε=0.1 は最後まで固定なので、後半も 1 割ランダムで更新し続ける。収束というより重みが揺れ続ける。

相手は常に自分自身である。探索や定石を持つ個体とは一度も対局しない。

### 1.3 位置評価の点数表との比較

5000 局後の `models/rl.json`（黒平面）と、ルールベース (位置評価) の固定表 [`POSITION_SCORES`](../strategy/src/reversi/agents/position_table.py) を、同じ 8×8 で比べた。位置評価は着手直後の自分の石の点数合計だけを見る。相手の石は引かない。解説は [`docs/catalog/positional.md`](catalog/positional.md) である。RL の黒平面は「自分の石がそのマスにあるときの寄与」に相当する。白平面はおおむねその符号反転で、ゼロサムとして整合している。切片は約 −0.003 である。

相関係数（64 マス）は次のとおりである。

| 比較 | 値 |
| --- | ---: |
| Pearson（位置評価 vs 黒平面） | 0.88 |
| 同上、四隅を除く | 0.32 |
| 同上、四隅と X を除く | 0.11 |
| Spearman（位置評価 vs 黒平面） | 0.51 |

全体の 0.88 は四隅が作っている。角の次に何を嫌うか、盤の内部の順位は揃っていない。

以下では、角の周りのマスをリバーシの慣用に従って呼び分ける。X マスは角から斜めに一つ内側のマスで、b2・g2・b7・g7 の 4 つである。C マスは角に辺の上で隣接するマスで、a2・b1・g1・h2・a7・b8・g8・h7 の 8 つである。どちらも、そこに自分の石を置くと、相手が角に打つためのはさむ条件ができやすい。角の石は二度と裏返らないので、角を渡す危険があるこれらのマスは一般に避けられる。

役割マスの平均は次のとおりである。

| 役割 | 位置評価 | RL 黒の平均 |
| --- | ---: | ---: |
| 角（a1, h1, a8, h8） | 100 | +0.241 |
| X（b2, g2, b7, g7） | −50 | −0.013 |
| C（角の隣） | −20 | +0.016 |
| その他の辺 | +7.5 | +0.021 |

角が最大なのは一致する。X の罰は位置評価ほど強くない。C は符号が逆である。位置評価は C を避けるが、RL はわずかにプラスである。

位置評価は 8 回対称が完全である。RL は崩れている。黒平面でいちばん重い角は h1（+0.258）、いちばん軽い X は b7（−0.021）である。初期重みがゼロのとき greedy の同点は a1…h8 なので、自己対局の偏りが残っている。

空平面の d4・e4・d5・e5 は 0 である。初形から埋まっているため、学習中に「空き」として一度も出ていない。

### 1.4 含意

5000 局で学んだのは「角が良い」までで、位置評価が人手で入れている X/C の罰までは再現していない。勝ち点が近いのは、どちらも 1 手先のマス点数で動くからである。表の中身が同じになったわけではない。

X/C の罰を再現できないのは、学習量の不足というより表現の限界である。X や C が危険なのは、隣の角がまだ空いているときに限られる。隣の角をすでに自分が取っていれば、X や C の石は角を渡す心配がなく、確定石を広げる足場になり得る。つまり X/C の価値は角の状態によって符号ごと変わる。マスごとに一つの重みしか持てない線形の配置特徴では、この条件付きの価値を書けず、二つの状況の平均として 0 付近の値に潰れる。C の平均がわずかにプラスになったのはこの結果と読める。

加えて、1.2 の比較そのものが改善を検出しにくい。総当たりは各相手と黒番・白番の 2 局ずつ、計 20 局である。RL も相手の多くも決定的なので、同じ組み合わせは何度対局しても同じ 2 局になる。この粒度では、評価関数が多少良くなっても勝敗が 1 局も動かないことは十分起こる。9.5 点と 9 点の差も、この局数では誤差と区別できない。

以上から、線形の配置特徴のまま局数だけを積んでも、読み（ミニマックス・αβ）や定石、Jev との差は埋まらない。改善の対象は表現・探索・学習手順の側であり、その前提として測定の粒度を上げる必要がある。ただし、これは「局数は効かない」という意味ではない。2.3 のように表現を豊かにすると重みの数が大きく増え、局数が再び効く側に回る。正確には「表現を変えてから局数を積む」である。

## 2. 方針

方針は五つからなる。測定の粒度を上げること、学んだ評価を探索に載せること、表現をパターン特徴に変えること、学習手順を整えること、探索側を拡張することである。前の二つは実装量が小さく、以降のすべての判断の土台になるので先に行う。

### 2.1 測定の粒度を上げる

いまの総当たりは、開始局面が常に初形で、個体が決定的なので、組み合わせごとに 2 局しか情報を持たない。ゲーム AI の評価では、開始局面を散らして局数を稼ぐのが通例である。

具体的には、初形からランダムな合法手を 4〜8 手打った局面を数百用意し、各局面から黒番・白番を入れ替えて 2 局ずつ対局する。開始局面の集合は seed 付きで生成してファイルに固定し、比較するどの個体にも同じ集合を使う。こうすると、個体が決定的でも局面ごとに異なる対局になる。

勝率の標準誤差は、勝率が 0.5 付近で独立な局数を \(N\) とすると \(\sqrt{0.25/N}\) 程度である。いまの 20 局なら約 0.11 で、95% の幅はおよそ ±22 ポイントになる。400 局なら約 0.025 で、幅はおよそ ±5 ポイントまで縮む。この見積もりは各局を独立とみなした近似であり、同じ開始局面の黒白 2 局は相関するので、実際の幅はこれよりやや広い。

学習の途中経過も記録する。学習 N 局ごとに重みのスナップショットを取り、固定の相手（ランダム (一様)、ルールベース (位置評価)、浅いミニマックス）に対する勝率と平均石差を測って学習曲線にする。学習は seed を変えて複数本走らせ、曲線のばらつきを見る。これにより、「学習が効いていない」のか「測定が粗くて見えない」のかを区別できる。

### 2.2 学んだ評価を探索に載せる

いまの RL は着手直後の \(v\) だけで手を選ぶので、構造上は位置評価と同じ 1 手読みである。ミニマックス・αβ に全敗なのは、評価の質以前に読みの深さの差でおおむね説明できる。ボードゲームで学習した評価関数は、探索と組み合わせて使うのが TD-Gammon 以来の通例である。

最初の実験として、既存のミニマックス／αβ の評価関数を `POSITION_SCORES` から RL の \(v\) に差し替え、同じ探索深さで両者を対局させる。探索を揃えれば、勝敗の差は評価関数の差だけから生じる。この比較を以降の改善の主指標にする。単独の 1 手読み RL の順位は、参考値として残す。

差し替えにあたって、白番の符号反転と、\(v\) の尺度（位置評価は整数点、RL は 1 未満の小数）の違いに注意する。αβ の枝刈りは評価値の大小関係だけを使うので、尺度の違い自体は問題にならない。ただし、評価値に何らかの閾値や定数ボーナスを足している箇所があれば、尺度を合わせる必要がある。

### 2.3 表現：パターン特徴に変える

1.4 のとおり、X/C のような「他のマスの状態に依存する価値」は、マスごとの独立な重みでは表せない。リバーシで実績がある表現は、パターン特徴（N-tuple 特徴とも呼ぶ）である。これは、盤上の決まったマスの組を一つの単位として取り、その組の黒・白・空の組み合わせ全体ごとに重みを持たせる方式である。Logistello 以来の強いリバーシ評価関数の多くがこの形をとり、N-tuple 特徴を TD 学習する方法もオセロで効果が報告されている（Lucas, Jaśkowski らの研究）。

代表的なマスの組は、辺＋2 つの X マス（10 マス）、角を含む 3×3（9 マス）、角を含む 2×5（10 マス）、長さ 4〜8 の斜め線、辺から 2〜4 列目の横列である。10 マスの組なら組み合わせは \(3^{10} = 59049\) 通りで、組ごとに同じ数の重みを持つ。たとえば「辺＋2X」の組は、角が空で X に自分の石がある状態と、角が自分で X に自分の石がある状態を別の項目として持つので、1.4 で述べた条件付きの価値をそのまま学べる。

評価値は、各組の該当項目の重みを足し合わせたものになる。評価はパターンの参照表を引いて足すだけなので線形のままであり、いまの TD(0) の更新式をほぼそのまま使える。変わるのは、更新される重みが「その局面で現れた各組の項目」になる点である。

パターン特徴には次の三つを合わせて入れる。

- 8 回対称の重み共有。盤を回転・反転して一致する組は同じ重み表を使う。1.3 の非対称（重い角が h1、軽い X が b7）が構造的に消え、1 局から得られる更新の数も実質的に増える。
- 段階別の重み。盤上の石数（または手数）で段階を分け、段階ごとに別の重み表を持つ。序盤と終盤ではマスや形の価値が大きく変わるためである。段階数は 10 前後を出発点にし、隣の段階の重みを初期値や平滑化に使うと、局数が少ない段階の学習を補える。
- スカラー特徴。着手可能数（mobility）、空きマスに接する石の数（潜在的 mobility、フロンティア）、残り空きマスの偶奇（パリティ）を線形項として足す。いずれも 1.1 で「入らない」とした量である。

いまの空平面は、黒＋白＋空＝1 から切片と線形従属であり、情報を増やしていない。パターン特徴へ移るときには不要になる。

パターン特徴は重みの数が数十万規模になるので、学習局数は現在の 5000 局では足りない。文献では 10^5〜10^6 局規模の自己対局が一般的である。局数の目安は 3.2 の学習曲線で決め、曲線が平らになったところを必要局数とみなす。

### 2.4 学習手順を整える

いまの学習手順で、強化学習の通例から外れている点は四つある。

一つめは減衰である。α と ε が固定なので、後半も同じ大きさで重みが揺れ続ける。学習の進行に合わせて α と ε を下げる。ε については、ε-greedy の代わりに 2.1 と同じ要領でランダムな開始局面から自己対局を始め、探索性を局面の多様さで確保する方法もある。

二つめは探索手の扱いである。いまの TD(0) は afterstate の価値を学ぶが、ε でランダムに選んだ手の後の局面を目標にして更新すると、学ぶ価値が貪欲方針ではなく探索込みの方針の価値に引っ張られる。ランダム手の直前では更新しないか、更新の目標を「その局面での貪欲手の afterstate 価値」にする。

三つめは報酬の伝播である。終局まで数十手あるリバーシでは、TD(0) だと終局の報酬が序盤の重みに届くまで多くの局を要する。TD(λ) にすると、1 局の中で報酬をまとめて遡らせられる。λ は 0.5〜0.9 程度を試す。

四つめは報酬の定義である。報酬を勝敗（+1/0/−1）にするか石差にするかを明示的に決め、`docs/catalog/rl.md` に書く。石差は 1 局ごとの信号が細かく学びやすい一方、勝率の最大化とは一致しない。勝敗は目的に直結するが信号が粗い。どちらを採るかは 3.2 の比較で決める。

パターン特徴に移ると 1 局面で更新される重みの数が組の数だけに増えるので、α を活性な項目数で割るなどの正規化も必要になる。

自己対局だけで学ぶと、自分同士でしか出ない偏った局面に学習が集中しやすい。過去の重みのスナップショットや、位置評価・浅いミニマックスを対戦相手のプールに混ぜると緩和できる。ただし、これは上の四点より優先度が低い。

### 2.5 探索側を拡張する

リバーシは終盤の完全読みが効くゲームである。残り空きマスが 10〜14 程度になれば、家庭用 PC でも終局まで読み切って最善手を選べる。この部分は評価関数の良し悪しと無関係に強さを上げる。評価関数の改善と効果を混同しないよう、3.2 では別の段階として扱う。

探索しながら評価関数を学ぶ TD-Leaf や TreeStrap という手法もある。探索の末端の値を学習目標に使うので、2.2 の探索付き運用と学習の条件が揃う。ただし実装と計算量が増えるので、2.3 と 2.4 の効果を確かめた後に検討する。

### 2.6 採らないもの

AlphaZero 型の方策・価値ネットワークと MCTS の組み合わせは、この実験の範囲では採らない。十分な強さに達するまでの自己対局の計算量が大きく、専用 GPU を前提にしないこのリポジトリの学習環境では費用対効果が悪いためである。ニューラルネットワークによる評価はすでに「ニューラルネットワーク (棋譜)」の個体が扱っている。

## 3. 検証

### 3.1 評価の土台

2.1 の測定を、以降のすべての比較で共通に使う。開始局面の集合、対局数、対戦相手、探索深さは段階をまたいで固定し、変える場合は記録に残す。

指標は勝率（引き分けを 0.5 勝として数える）、平均石差、その 95% 区間である。改善と判定するのは、比較対象に対する勝率の 95% 区間が 0.5 を上回ったときとする。区間が 0.5 をまたぐ場合は、差がないのではなく、その局数では区別できないと記録する。

結果の正本は、これまでと同じく総当たり JSON と学習成果物である。どの `models/` の blob に対する結果かを JSON の `git.blobs` に残し、段階ごとの推移を [`history.md`](benchmarks/history.md) に追記する。

### 3.2 段階と比較

変更は段階ごとに一つずつ入れ、各段階で 3.1 の測定を回す。こうすれば、どの変更が効いたかを切り分けられる。段階の順序と Issue は次のとおりである。


段階 0 では、2.1 の開始局面集合と学習曲線の仕組みを作り、いまの 5000 局モデルを測り直す。ここで得た値が以降の基準線になる。1.2 の総当たりと傾向が合うかも確かめる。

段階 1 では、2.2 の差し替えを行う。比較は「αβ＋`POSITION_SCORES`」対「αβ＋いまの RL の \(v\)」で、深さを 1・2・4 程度で揃える。いまの RL は X/C を学べていないので、この段階では位置評価に負けることもあり得る。負けた場合も、以降の段階の比較の枠組みとしてそのまま使う。

段階 2 では、表現は変えずに 2.4 の小さな修正（α と ε の減衰、探索手の更新除外、対称の重み共有、空平面の削除）を入れる。比較対象は段階 1 の RL である。表現が同じなので、効果は小さいと予想する。ここでは主に、学習曲線が揺れずに平らになるかを確かめる。

段階 3 では、2.3 のパターン特徴、段階別の重み、スカラー特徴と、2.4 の TD(λ) を入れる。比較対象は段階 2 の RL と、「αβ＋`POSITION_SCORES`」である。報酬を勝敗にするか石差にするかもここで比べる。学習局数は学習曲線が平らになるまで増やし、必要局数を記録する。この段階で X/C の重みが角の状態によって符号を変えているかを、重み表から直接確かめる。これは 1.3 の分析の続きにあたる。

段階 4 では、2.5 の終盤完全読みを入れる。比較は同じ評価関数で完全読みの有無だけを変えたもの同士とし、評価関数の改善と効果を混同しないようにする。完全読みを始める空きマス数は、1 手あたりの思考時間の上限から決める。

いずれの段階でも、最後にこれまでと同じ総当たりを回し、カタログ全体での順位を記録する。ただし改善の判定には 3.1 の指標を使い、総当たりの順位は参考値とする。

## 4. カタログ上の扱い

改善後の個体は、いまの `rl` を置き換えず、別の個体としてカタログに追加する。いまの線形 TD(0) は「表現が貧しいと何が起きるか」を示す比較対象として価値があり、3.2 の各段階の基準線にもなるので、そのまま残す。新しい個体の `SPECIMEN_ID` と学習成果物のファイル名は、実装時に決める。

新しい個体の分類は「強化学習」とする。カタログの分類は、評価の中身をどうやって得たかで分けている。「ルールベース (ミニマックス)」がルールベースなのは、読みを使うからではなく、評価に使う点数表を人が書いているからである。新しい個体は、着手の選び方こそミニマックス・αβ と同じく数手先を読むが、評価関数は自己対局の強化学習で得る。何を良い局面とみなすかという知識の出どころが強化学習にあるので、分類は強化学習になる。

同じ分類に既存の「強化学習 (自己対局)」が並ぶので、表示名の括弧書きで読みの有無が分かるようにする（例: 「強化学習 (自己対局＋読み)」）。説明文には、評価を自己対局で学ぶことと、着手は数手先を読んで選ぶことの両方を書く。
